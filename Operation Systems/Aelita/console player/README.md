# cam-player — просмотр одной камеры в окне (Aelita 24 / xrdp)

`cam-player` показывает **один** поток с камеры (RTSP/HTTP/HLS) в отдельном небольшом окне.
Ссылка на поток передаётся аргументом в консоли, окно по умолчанию 640×360 с рамкой —
не на весь экран, поверх других окон его можно двигать и закрывать как обычное.

Работает без GPU: декодирование программное (`ffmpeg`), вывод через SDL2 — это единственный
вариант, который стабильно живёт в сессии `xrdp`/`xorgxrdp` (аппаратного OpenGL там нет).

Проверено на Aelita 24 (x86_64, 4 vCPU, 5.5 ГБ RAM, без GPU), xrdp 0.10.6 + xorgxrdp 0.10.5,
Xfce 4.16, сессия 2560×1440: H.264 и H.265, окна 640×360 / 720×404 / 960×540, ~8–10 % одного
ядра на поток.

---

## 1. Что умеет и чего не умеет

| Умеет | Не умеет (сознательно) |
|---|---|
| один поток: `rtsp(s)://`, `http(s)://`, `hls`, `srt://`, `file://` | несколько камер в одном окне |
| H.264, H.265/HEVC, MJPEG, MPEG-4 | запись, снимки, архив, детекцию движения |
| звук по флагу `--audio` (AAC, G.711) | PTZ, управление камерой, ONVIF-обнаружение |
| размер окна `--size`, ограничение fps, `tcp/udp` | аппаратное декодирование (в xrdp его нет) |
| проверку потока без открытия окна: `--check` | зум колесом/перетаскивание внутри окна |
| пароль в файле (`--url-file`), чтобы не светить его в `ps` | авторизация по ONVIF-учётке вместо URL |

## 2. Требования

| Компонент | Требование |
|---|---|
| ОС | Aelita 24 (x86_64, `ID_LIKE=anolis`, EL8-совместимая) |
| Графика | X11 + Xfce; штатный сценарий — сессия xrdp (`xrdp` + `xorgxrdp`) |
| `ffmpeg` | 4.2.4 из репозитория `aelita-ru` (пакет `ffmpeg`, 34 пакета / 20 МБ, конфликтов нет) |
| Утилиты | `bash`, `sed`, `mktemp` — есть в базовой системе |
| Права | установка от `root`; запуск — от обычного пользователя (не `root`) |
| Место | сам скрипт ~5 КБ |

Почему именно `ffmpeg`, а не «обычный плеер» (проверялось `dnf --assumeno install` на Aelita 24):

| Вариант | Итог |
|---|---|
| **ffmpeg 4.2.4 (`aelita-ru`)** | **ставится штатно**, все нужные кодеки и протоколы внутри |
| VLC 3.0.24 (RPM Fusion free el8) | не ставится: требует `libdvdread.so.4`, в Aelita 24 `libdvdread.so.6` |
| mpv 0.34.1 (RPM Fusion free el8) | не ставится: `libcdio.so.18` + `libdvdread.so.4` |
| Chromium 133 (`epel8-ru`) | H.264/HEVC отсутствуют: `MediaSource.isTypeSupported(...avc1...)` → `false` |
| Firefox | в репозиториях Aelita отсутствует |

## 3. Установка на компьютер заказчика

Все команды ниже — от `root` на самой машине (или через `ssh`/`sudo`).

### 3.1. Проверить репозитории

Нужны включёнными `aelita-ru` (основной) и, как правило, `epel8-ru`. Их подготовка описана в
соседнем документе — `../README.md`, раздел 2 («Репозитории»).

```bash
dnf repolist
```

Ожидаемо как минимум:

```
repo id      repo name
aelita-ru    Aelita 24 - RU mirror (repo.aelita.itgryphon.ru)
epel8-ru     EPEL 8 - mirror.yandex.ru
```

### 3.2. Поставить `ffmpeg`

```bash
dnf -y install ffmpeg
ffmpeg -hide_banner -version | head -1
```

Ожидаемо: `ffmpeg version 4.2.4` (сборка `--enable-libx264`, `--enable-gnutls`, `--enable-libsrt`).

Проверить, что нужное для камер на месте:

```bash
ffmpeg -hide_banner -demuxers 2>/dev/null | grep -E ' rtsp '
ffmpeg -hide_banner -decoders 2>/dev/null | grep -E ' (h264|hevc|mjpeg|pcm_alaw|aac) '
```

Должны найтись `rtsp`, `h264`, `hevc`, `mjpeg`, `aac`, `pcm_alaw`.

### 3.3. Перенести скрипт на машину

С машины, где скрипт уже лежит (например, с этой ВМ):

```bash
# на источнике
sha256sum cam-player        # запомнить/передать хеш
scp cam-player root@<IP-клиента>:/tmp/cam-player
```

Без сети (флешка, общий каталог) — скопировать файл любым способом и сверить хеш:

```bash
# на целевой машине
sha256sum /tmp/cam-player
# хеш должен совпасть с тем, что на источнике
```

Если файл копировался через Windows/архив, при переносе может появиться CRLF — проверить:

```bash
file /tmp/cam-player      # должно быть: POSIX shell script, ASCII text executable
grep -c $'\r' /tmp/cam-player   # должно быть 0
```

### 3.4. Установить и проверить синтаксис

```bash
install -m 0755 /tmp/cam-player /usr/local/bin/cam-player
bash -n /usr/local/bin/cam-player && echo "syntax OK"
cam-player -h
```

`/usr/local/bin` уже есть в `PATH` интерактивных сессий Xfce. В `sudo`/`su` действует
`secure_path`, поэтому там запускайте полным путём: `/usr/local/bin/cam-player`.

### 3.5. Проверить на реальной камере

Сначала — без открытия окна (можно и по ssh, `DISPLAY` не нужен):

```bash
cam-player --check 'rtsp://admin:ПАРОЛЬ@192.168.0.71:554/Streaming/Channels/102'
```

```
OK    1280x720 h264 25 fps   rtsp://admin:***@192.168.0.71:554/Streaming/Channels/102
```

Затем — окно, уже в графической сессии (xrdp или локально):

```bash
cam-player 'rtsp://admin:ПАРОЛЬ@192.168.0.71:554/Streaming/Channels/102'
```

Должно открыться окно 640×360 с рамкой, в заголовке — ссылка с замаскированным паролем,
в терминале — строка `cam-player: 640x360, rtsp://admin:***@…`.

Выход: `q` в окне или `Ctrl+C` в терминале.

### 3.6. Пароли камер

Если ссылку с паролем передавать аргументом, её видно другим пользователям в `ps` и в истории
shell. Для рабочих машин используйте файл со ссылкой:

```bash
# от имени пользователя, который будет смотреть
install -m 0600 -o test1 -g test1 /dev/null /home/test1/.cam-vhod.url
printf '%s\n' 'rtsp://admin:ПАРОЛЬ@192.168.0.71:554/Streaming/Channels/102' > /home/test1/.cam-vhod.url
chmod 600 /home/test1/.cam-vhod.url

cam-player -u /home/test1/.cam-vhod.url
```

Файл читается первым непустым некомментированным строкой; права `0600` и владелец —
пользователь, который запускает `cam-player`.

Дополнительно: заведите на камерах отдельные учётные записи с правами «только просмотр» —
пароль попадёт в конфигурацию рабочего места и не должен давать доступ к настройкам
регистратора.

### 3.7. Ярлык в меню (необязательно)

Одна камера — один ярлык. Удобно, когда сотруднику нужно «одна кнопка — вход».

```bash
cat > /usr/share/applications/cam-vhod.desktop <<'X'
[Desktop Entry]
Type=Application
Version=1.0
Name=Камера: вход
Comment=Просмотр камеры «Вход»
Exec=/usr/local/bin/cam-player -u /home/test1/.cam-vhod.url --title "Вход"
Icon=camera-web
Terminal=false
Categories=AudioVideo;
X
desktop-file-validate /usr/share/applications/cam-vhod.desktop
```

Если ярлык нужен только одному пользователю — положите его в `~/.local/share/applications/`
(в файле пути должны быть с его домашним каталогом).

### 3.8. Обновление скрипта

```bash
scp cam-player root@<IP>:/tmp/cam-player && ssh root@<IP> '
  sha256sum /tmp/cam-player &&
  install -m 0755 /tmp/cam-player /usr/local/bin/cam-player &&
  cam-player -h >/dev/null && echo updated'
```

Скрипт не пишет ничего в систему, кроме самого файла, поэтому обновление — это замена файла.
Запущенные экземпляры продолжают работать на старой версии до закрытия окна.

### 3.9. Удаление

```bash
rm -f /usr/local/bin/cam-player
rm -f /usr/share/applications/cam-vhod.desktop ~/.local/share/applications/cam-vhod.desktop
rm -f /home/test1/.cam-vhod.url
# ffmpeg удаляйте только если он больше нигде не нужен
dnf -y remove ffmpeg
```

## 4. Параметры

```
cam-player [параметры] <URL потока>
```

| Параметр | Значение по умолчанию | Описание |
|---|---|---|
| `<URL>` (позиционный) | — | ссылка на поток: `rtsp://`, `rtsps://`, `http(s)://`, `hls`, `srt://`, `file://`. Обязателен, если не задан `--url-file` |
| `-s, --size WxH` | `640x360` | размер окна в пикселях. Нечётные значения уменьшаются до чётных (`720x405` → `720x404`) |
| `-t, --transport tcp\|udp` | `tcp` | транспорт RTSP. Применяется только к `rtsp(s)://`; `tcp` надёжнее через NAT/VPN, `udp` чуть меньше задержка в локальной сети |
| `-f, --fps N` | без ограничения | ограничить частоту кадров («взять 25 fps с камеры, показывать 10»); снижает нагрузку CPU и трафик RDP |
| `--title ТЕКСТ` | `cam-player — <URL>` | заголовок окна. Пароль в автоматическом заголовке маскируется |
| `--audio` | выключен | воспроизводить звук потока (иначе `-an`) |
| `--ffmpeg-args "…"` | — | дополнительные ключи **входа** ffmpeg, например `-tls_verify 0`, `-timeout 5000000`, `-rtsp_flags prefer_tcp` |
| `-u, --url-file ФАЙЛ` | — | взять ссылку из файла (первая непустая некомментированная строка). Взаимоисключающе с позиционным URL |
| `-c, --check` | — | только проверить поток через `ffprobe` (кодек, разрешение, fps) и выйти; `DISPLAY` не нужен |
| `-h, --help` | — | справка |

Правила разбора:

* любую опцию можно писать как `--size 800x600`, так и `--size=800x600`;
* порядок опций и URL произвольный: `cam-player rtsp://… --size=800x600` работает;
* код возврата: `0` — нормальный выход или успешный `--check`; `1` — ошибка (недоступный поток,
  неверные параметры, нет `DISPLAY`, нет `ffmpeg`).

## 5. Примеры

```bash
# основная камера
cam-player 'rtsp://admin:ПАРОЛЬ@192.168.0.71:554/Streaming/Channels/101'

# субпоток (меньше нагрузка) — типично для просмотра в xrdp
cam-player --size 960x540 'rtsp://admin:ПАРОЛЬ@192.168.0.71:554/Streaming/Channels/102'

# ссылка из файла + свой заголовок
cam-player -u ~/.cam-vhod.url --title "Вход"

# проверка без окна
cam-player --check -u ~/.cam-vhod.url

# UDP (локальная сеть, низкая задержка)
cam-player --transport=udp --size=800x600 'rtsp://admin:ПАРОЛЬ@192.168.0.72:554/cam/realmonitor?channel=1&subtype=1'

# ограничение fps и уменьшенное окно
cam-player -f 10 -s 640x360 'rtsp://admin:ПАРОЛЬ@192.168.0.73:554/onvif/profile2/media.smp'

# самоподписанный сертификат на rtsps
cam-player --ffmpeg-args "-tls_verify 0" 'rtsps://admin:ПАРОЛЬ@192.168.0.74:554/live'

# звук с камеры
cam-player --audio 'rtsp://admin:ПАРОЛЬ@192.168.0.75:554/Streaming/Channels/101'
```

Полезные шаблоны URL (уточняйте по документации модели):

| Вендор | Основной поток | Субпоток |
|---|---|---|
| Hikvision | `/Streaming/Channels/101` | `/Streaming/Channels/102` |
| Dahua | `/cam/realmonitor?channel=1&subtype=0` | `…&subtype=1` |
| XM/OEM | `/live/ch0` | `/live/ch1` |
| универсальный ONVIF | `/onvif/profile1/media.smp` | `/onvif/profile2/media.smp` |
| MJPEG по HTTP | `http://admin:ПАРОЛЬ@IP/mjpg/video.mjpg` | — |

## 6. Как ведёт себя окно

* окно **с рамкой**, ровно заданного размера, не полноэкранное и не «borderless»;
* пропорции сохраняются: если соотношение сторон потока и окна различаются, по краям чёрные
  поля (картинка не растягивается);
* заголовок — `cam-player — <URL>` с замаскированным паролем (`admin:***@`), либо `--title`;
* позицию окна выбирает оконный менеджер Xfce (обычно по центру); перетаскивается мышью
  за заголовок;
* `q` в окне или `Ctrl+C` в терминале — выход; закрытие крестиком также завершает процесс;
* при обрыве связи `ffmpeg` пишет ошибки в терминал и завершается — окно закрывается.

## 7. Производительность (замеры)

Замеры на эталонной ВМ: 4 vCPU (QEMU без AVX), 5.5 ГБ RAM, GPU нет, сессия xrdp 2560×1440.

| Сценарий | CPU | RAM |
|---|---|---|
| окно 640×360 из потока 720p H.264 | ~8–10 % одного ядра | ~120 МБ |
| окно 720×404 из потока 360p H.264 | ~7 % одного ядра | ~115 МБ |
| декодирование 1080p H.264 «в никуда» (`-f null`) | ~7.5 % | — |
| 4 потока 1080p одновременно (для справки) | ~33 % | — |

Практика:

* 1 камера в окне 640×360 — практически незаметная нагрузка, можно держать открытой постоянно;
* для xrdp важнее не декод, а площадь окна и fps: уменьшайте `--size` и `-f`, прежде чем
  «добавлять железо»;
* на клиенте RDP ставьте 24 bpp и отключите сглаживание шрифтов — трафик заметно ниже;
* субпоток камеры (D1/720p) дешевле основного (1080p/4K) и для наблюдения обычно достаточен.

## 8. Диагностика

| Симптом | Причина | Решение |
|---|---|---|
| `cam-player: DISPLAY не задан` | запуск по ssh без графической сессии | запускать в сессии xrdp/X11; для проверки потока — `--check` |
| `cam-player: не найден ffmpeg` | пакет не установлен/не в `PATH` | `dnf -y install ffmpeg` |
| `FAIL … 401 Unauthorized` | неверный логин/пароль, учётка заблокирована | проверить учётку камеры, права «только просмотр» |
| `FAIL … 404 Not Found` | неверный путь потока | сверить шаблон URL по модели камеры (раздел 5) |
| `FAIL … Connection timed out` / `Connection refused` | камера недоступна, другой порт, блокировка | `ping IP`, `ss -tn | grep 554`, проверить firewall |
| `FAIL … Invalid data found when processing input` | это не видеопоток (HTML-страница, .jpg) | взять RTSP-ссылку, а не ссылку веб-интерфейса |
| Картинка «тормозит», в терминале `max delay reached`, `RTP: missed N packets` | потери UDP-пакетов | `--transport tcp`, уменьшить `--size` и `-f` |
| Первые 1–2 с HEVC-картинка битая/зелёная | декодер ждёт ключевой кадр (GOP камеры 2–4 с) | подождать 1–2 с; на камере уменьшить интервал ключевых кадров |
| Пароль с `@`, `#`, `&`, `/`, пробелом или кириллицей не подходит | служебные символы в URL | закодировать в percent-encoding (`@`→`%40`, `#`→`%23`, `&`→`%26`), либо сменить пароль камеры на буквы/цифры |
| `-tls_verify` / ошибка сертификата на `rtsps://` | самоподписанный сертификат | `--ffmpeg-args "-tls_verify 0"` (осознанно), либо поставить CA камеры в систему |
| Окно открылось, но чёрное | поток H.265, а ffmpeg собран без HEVC | проверить `ffmpeg -decoders | grep hevc`; при отсутствии — обновить пакет `ffmpeg` |
| `Could not initialize SDL` | нет доступа к X-серверу | запускать под тем пользователем, у которого открыта сессия, с его `DISPLAY`/`XAUTHORITY` |

Ручная проверка в обход скрипта:

```bash
ffprobe -v error -rtsp_transport tcp -show_streams 'rtsp://…' | head -30
ffplay  -rtsp_transport tcp -fflags nobuffer -flags low_delay -framedrop \
        -probesize 32 -analyzeduration 0 'rtsp://…'
```

## 9. Известные ограничения

* один поток на процесс; несколько камер — это несколько окон `cam-player`;
* запись, снимки, архив и PTZ не поддерживаются (это плеер, а не клиент регистратора);
* аппаратного декодирования нет — в xrdp отсутствует VA-API/GL, всё делает CPU;
* ffmpeg 4.2 — стабильная ветка EL8; 10-битные HEVC/HDR-потоки камерами практически не
  используются, но на экзотических моделях возможны проблемы с цветом;
* позиция окна не запоминается (её задаёт оконный менеджер);
* ссылка, переданная аргументом, видна в `ps` и истории команд — используйте `--url-file`.

## 10. Чек-лист внедрения на машине

- [ ] `dnf repolist` — есть `aelita-ru` (и `epel8-ru`)
- [ ] `dnf -y install ffmpeg`, `ffmpeg -version` → 4.2.4
- [ ] `ffmpeg -demuxers` содержит `rtsp`, `-decoders` содержит `h264` и `hevc`
- [ ] `sha256sum cam-player` совпал с источником, в файле нет CRLF
- [ ] `install -m 0755 cam-player /usr/local/bin/cam-player`, `bash -n` и `cam-player -h` проходят
- [ ] `cam-player --check 'rtsp://…'` → `OK`, код возврата `0`
- [ ] окно открывается в сессии xrdp, `q`/`Ctrl+C` закрывают его
- [ ] пароль вынесен в файл `0600` (`--url-file`), в ярлыке/команде его нет
- [ ] учётка на камере — «только просмотр»
- [ ] размер окна и `-f` подобраны по нагрузке (раздел 7)
- [ ] известна процедура обновления и удаления (3.8, 3.9)
